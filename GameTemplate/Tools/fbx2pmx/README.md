# fbx2pmx — FBX モデルを MMD の PMX 形式へ変換するツール

FBX ファイルを MikuMikuDance (MMD) / PMXEditor で読める **PMX 2.0** へ変換します。
Python だけで動き、Autodesk FBX SDK も Blender も不要です。

- 対応入力: バイナリ FBX (7.x) / ASCII FBX
- 対応出力: PMX 2.0 (文字コード UTF-16LE)
- 必要環境: Python 3.8 以降 (追加ライブラリ不要)
- 人型モデルは **足ＩＫ付きの MMD 標準ボーン構造**に整えるので、
  ネットで配布されているモーション(VMD)をそのまま流せます(後述)
- 髪・スカート・袖などには **剛体とジョイント(物理)を自動で付けます**(後述)
- MMD が読めない DDS テクスチャは PNG / TGA へ変換できます(後述)

## 使い方

```bat
python fbx2pmx.py model.fbx
```

`model.fbx` と同じ場所に `model.pmx` ができます。
Windows では `fbx2pmx.bat` に **FBX をドラッグ＆ドロップ**しても変換できます。
**FBX とテクスチャ画像(またはテクスチャの入ったフォルダ)をまとめてドロップ**すると、
材質ごとのテクスチャを自動で割り当てます(後述)。

```bat
rem 出力先を指定
python fbx2pmx.py model.fbx -o out\model.pmx

rem テクスチャ画像やフォルダを一緒に渡す(割り当ての候補になる)
python fbx2pmx.py model.fbx body.png face.png hair.png -o out
python fbx2pmx.py model.fbx --texture-dir D:\download\model\textures -o out

rem フォルダ内の .fbx をまとめて変換
python fbx2pmx.py ..\..\Game\Assets\modelData -o out
```

### 主なオプション

| オプション | 説明 |
| --- | --- |
| `-o, --output PATH` | 出力する `.pmx` のパス、または出力フォルダ |
| `--scale N` | 頂点座標に掛ける倍率。省略時は FBX の単位から自動計算 |
| `--unit {mmd,meter,raw}` | `--scale` 省略時の基準。既定は `mmd` (1 単位 ≒ 8cm) |
| `--yaw {auto,角度}` | Y 軸まわりの回転。既定の `auto` はつま先ボーンから正面を推定 |
| `--max-weights {1,2,4}` | 1 頂点あたりの最大ボーン数 (既定 4) |
| `--keep-bone-names` | ボーン名を MMD 標準名へ変換せず FBX のまま出力 |
| `--bone-map JSON` | `{"FBXボーン名": "MMDボーン名"}` の JSON で名前を上書き |
| `--rig {mmd,none}` | `mmd`(既定)は標準ボーン構造・足ＩＫ・両目を整える。`none` は FBX の骨格のまま |
| `--arm-angle {auto,off,角度}` | 腕の下がり角。`auto`(既定)は T スタンスのときだけ 35 度へ直す |
| `--keep-morph-names` | 表情モーフ名を `あ` `まばたき` などへ変換しない |
| `--morph-map JSON` | `{"FBXのモーフ名": "MMDのモーフ名"}` の JSON で名前を上書き |
| `--no-wink` | `まばたき` `笑い` から `ウィンク` 系のモーフを作らない |
| `--physics {auto,none}` | `auto`(既定)は髪・スカート・袖などに剛体とジョイントを付ける |
| `--keep-material` | 材質の色・トゥーン・輪郭線・両面描画を MMD 向けに調整しない |
| `--name` / `--comment` | PMX のモデル名・コメント |
| `--texture-dir DIR` | テクスチャを探すフォルダを追加(複数指定可) |
| `--texture-map JSON` | `{"材質名": "画像"}` の JSON で割り当てを指定(`null` でテクスチャなし) |
| `--copy-textures` | 出力先の中にある画像も含め、すべて出力先へコピー |
| `--no-convert-textures` | DDS など MMD が読めない画像を PNG へ変換しない(既定は変換する) |
| `--texture-format {png,tga}` | 変換したテクスチャの出力形式 (既定 `png`) |
| `--texture-max-size N` | テクスチャの長辺が N を超える場合に縮小 |
| `--no-morph` | ブレンドシェイプをモーフへ変換しない |
| `--no-edge` / `--double-sided` | マテリアルの輪郭線を切る / 両面描画にする |
| `--flip-faces` | 面の表裏が逆になったときに巻き順を反転 |

変換後の中身を確認するツールも付いています。

```bat
python pmxinfo.py model.pmx --materials --bones --morphs --physics
```

## 変換される内容

| FBX | PMX | 備考 |
| --- | --- | --- |
| メッシュ(複数可) | 1 つのモデルへ統合 | 多角形は三角形に分割 |
| 法線 / UV | 頂点法線 / UV | UV は上下反転(PMX は原点左上) |
| マテリアル | 材質 | MMD 向けに調整(後述「見た目の調整」) |
| テクスチャ | テクスチャ(拡散のみ) | 自動割り当て・DDS は PNG へ変換(後述) |
| スキン(Cluster) | BDEF1 / BDEF2 / BDEF4 | 影響度上位 N 本を正規化 |
| ボーン階層 | ボーン | バインドポーズ(TransformLink)基準 |
| ブレンドシェイプ | 頂点モーフ | `あ` `まばたき` など MMD の標準名へ読み替え。`ウィンク` 系を追加 |
| — | 足ＩＫ / つま先ＩＫ / グルーブ / 両目 | 人型モデルに自動追加(後述) |
| — | 剛体 / ジョイント | 髪・スカート・袖などの揺れものと当たり判定を自動生成(後述) |
| — | 表示枠 | センター / 体(上) / 腕 / 指 / 体(下) / 足 / 表情 |

### 座標系・単位

FBX は右手座標系で、上方向や正面方向はファイル内の `GlobalSettings`
(`UpAxis` / `FrontAxis` / `CoordAxis`) で決まります。本ツールはその指定を読んで
**PMX の左手座標系 (Y 上・正面 -Z)** へ変換し、鏡像変換になる分だけ面の巻き順を
戻します。単位は `UnitScaleFactor` から実寸(メートル)を求め、MMD の縮尺
(1 単位 ≒ 8cm、身長 158cm で約 20 単位) に合わせます。

### ボーン名の MMD 標準名への変換

Mixamo (`mixamorig:Hips`)、Autodesk の `Character1_*`、3ds Max Biped (`Bip001 *`)、
Unity Humanoid 風 (`LeftUpperArm`、`UpperArm.L` など) の名前を
`センター` `上半身` `首` `頭` `左腕` `左ひじ` `左手首` `左足` `左ひざ` `左足首`
`左親指１` … といった MMD 標準名へ読み替えます(元の名前は英語名欄に残します)。
表にない名前はそのまま出力されます。`--bone-map` で個別に上書きでき、
`--keep-bone-names` で変換自体を止められます。

## 配布モーション (VMD) を使う

ネットで配布されているダンス・ライブ用のモーション(.vmd)は、MMD 付属の
初音ミクに倣った「標準ボーン」を前提に作られています。人型のモデルは、変換時に
自動でこの構造に整えます(`--rig mmd`、既定)。MMD でモデルを読み込んだあと、
VMD をそのまま読み込めば動きます。

| 整える内容 | 中身 |
| --- | --- |
| 親子関係 | `全ての親` → `センター` → `グルーブ` → `上半身` / `下半身`(上半身を下半身から切り離す) |
| 足ＩＫ | `左足ＩＫ`(対象 `左足首`、リンク `左ひざ`・`左足`、ひざは前にだけ曲がるよう角度制限)と `左つま先ＩＫ`。右も同様 |
| つま先 | つま先ボーンが無いモデルは、足首に乗っている頂点の最前端に `左つま先` / `右つま先` を補う |
| 両目 | `左目` / `右目` に回転を付与する `両目` を追加 |
| 腕の角度 | T スタンス(腕がほぼ水平)のモデルは 35 度下げた A スタンスにする(メッシュも一緒に回す) |
| 表情モーフ | `MTH_a` → `あ`、`EYE_blk` / `Blink` → `まばたき` など、リップシンク・まばたき用の名前へ。さらに `まばたき` を左右に分けて `ウィンク` / `ウィンク右`、`笑い` から `ウィンク２` / `ウィンク２右` を作る |

人型と判定できない(上半身や左右の足が無い)小物や武器には適用しません。

- 腕の高さがモーションと合わないときは `--arm-angle 40` のように角度を指定してください。
- 表情が動かないときは、VMD 側のモーフ名に合わせて `--morph-map` で名前を指定してください。
- `腕捩` `手捩` `肩P` `足D` `腰キャンセル` などの準標準ボーンは作りません。これらを使う
  モーションは、PMXEditor の準標準ボーン追加プラグインで足してから読み込んでください。
## 物理(髪・スカートの揺れ)

FBX には物理演算の情報が入っていないので、ボーン名と頂点の付き方から剛体と
ジョイントの叩き台を自動で作ります(`--physics auto`、既定)。

| 対象 | 判定に使う名前(ボーン名の一部) | 作るもの |
| --- | --- | --- |
| 髪 | `hair` `髪` `bangs` `pony` `twintail` `ahoge` など | 物理演算のカプセル + ジョイント |
| リボン | `ribbon` `リボン` | 同上(形を保つよう硬め) |
| スカート | `skirt` `スカート` `dress` `cape` `coat` など | 同上 |
| 袖 | `sode` `sleeve` `袖` `cuff` | 同上 |
| その他 | `tail` `しっぽ` `string` `紐` `frill` など | 同上 |
| 当たり判定 | `頭` `上半身` `下半身` `足` `ひざ` `腕` `ひじ` | ボーン追従のカプセル |

- 揺れもののボーン 1 本ごとに、そのボーンから子ボーンへ伸びるカプセルを置きます。
  先端のボーンは、乗っている頂点の広がりから長さを決めます。太さも頂点から推定し、
  左右対になるもの(`J_L_xxx` / `J_R_xxx`)はそろえます。
- 連鎖の付け根は、親ボーンの当たり判定(髪なら `頭`、スカートなら `下半身`)に
  ジョイントでつなぎます。
- 揺れもの同士、および付け根の当たり判定とはぶつかりません。脚・腕・胴とはぶつかるので、
  脚を上げるとスカートが押し出されます。
- 静止状態で重なっている剛体同士は、ぶつからない設定にします(初期フレームで暴れる
  原因になるため)。

揺れ方(重さ・減衰・ジョイントの角度制限・ばね)はあくまで叩き台です。揺れすぎる・
硬すぎる場合は PMXEditor で調整してください。物理を付けたくないときは
`--physics none`。

## 見た目の調整

ゲーム用の材質の値のままだと、MMD では暗く沈んだり平板に見えたりします。そこで
次のように調整します(`--keep-material` で無効化)。

- テクスチャのある材質は拡散色を白、環境色を 0.5 にし、色をテクスチャに任せる
- 共有トゥーン `toon01.bmp` を設定する
- 反射色を弱める(ゲーム用の強い反射でテカらないように)
- 目まわり(`eye` `目` `瞳` `まつげ` など)と半透明の材質は輪郭線を消す
- 髪・リボン・スカート・袖など薄い板の材質は両面描画にする

## テクスチャの自動割り当て

配布モデルの FBX は、テクスチャの参照が作者の PC の絶対パスのままだったり、拡張子が
違っていたり、そもそも繋がっていなかったりします。そのため材質ごとに次の順で画像を
探します。手がかりにするのは、FBX と同じフォルダ(と `textures` などのサブフォルダ)、
一緒に渡した画像、`--texture-dir` のフォルダです。

| 順 | 見つけ方 | 例 |
| --- | --- | --- |
| 1 | 割り当て表(`--texture-map`) | `{"Skin": "body.png"}` |
| 2 | FBX の参照どおり / 同じファイル名 | 参照 `C:\Users\作者\Body_D.tga` → 候補の `Body_D.tga` |
| 3 | 拡張子違い(大文字小文字も無視) | 参照 `Body_D.tga` → 候補の `body_d.PNG` |
| 4 | FBX に埋め込まれた画像を取り出す | `hair.png` を出力先へ書き出す |
| 5 | 材質名などとファイル名の近さで推定 | 材質 `Face` → `Face_BaseColor.png`(`Face_Normal.png` は除外) |
| 6 | 一緒に渡した拡散色の画像が 1 枚だけならそれ | アトラス 1 枚のモデル |

法線・スペキュラ・ラフネス・AO・発光などのマップ(`_Normal` `_nrm` `_spec` `_metallic`
など)は推定の候補から外します。変換ログに材質ごとの結果が出ます。

```
  テクスチャの割り当て:
    Body   ← body_d.PNG  [拡張子違い]
    Face   ← Face_BaseColor.png  [名前から推定]
    Hair   ← hair.png  [埋め込み]
    Skin   (なし)
```

推定や未発見の材質があったときは、PMX の隣に `<モデル名>_textures.json` を書き出します。
間違っている材質だけ書き換えて `--texture-map <モデル名>_textures.json` を付けて変換し
直せば、次からはその割り当てで変換されます(1 個ずつ PMXEditor で直す必要はありません)。

```json
{
  "Body": "../tex/body_d.PNG",
  "Face": "../tex/Face_BaseColor.png",
  "Skin": null
}
```

使う画像は PMX のフォルダへコピー(MMD が読めない形式は変換)するので、出力フォルダ
だけで完結します。

## テクスチャの変換 (DDS → PNG / TGA)

MMD が読めるのは BMP / PNG / JPEG / TGA だけで、**DDS は読めません**。
DDS など MMD が読めない画像は、変換時に自動で PNG へ変換して PMX と同じフォルダへ
書き出し、PMX からはその PNG を参照します(`--no-convert-textures` で無効化)。

```bat
rem 4K テクスチャを 2048 まで落としつつ変換
python fbx2pmx.py model.fbx -o out --texture-max-size 2048
```

テクスチャだけを変換したいときは単体でも使えます。

```bat
python texconv.py utc_all2.DDS                       rem 同じ場所に .png を作る
python texconv.py ..\..\Game\Assets\modelData -o tex rem フォルダ内の DDS をまとめて
python texconv.py normal.DDS --format tga --max-size 1024
```

対応している DDS は次のとおりです。

| 形式 | 内蔵デコーダ | Pillow |
| --- | --- | --- |
| DXT1 / DXT3 / DXT5 (BC1/BC2/BC3) | ○ | ○ |
| BC4 / BC5 (ATI1 / ATI2) | ○ | ○ |
| 無圧縮 RGB / RGBA / BGRA (マスク指定・DX10 含む) | ○ | 一部不可 |
| BC7 / BC6H | × | ○ |

Pillow が入っていればまず Pillow で読み、読めない形式(`B8G8R8A8_UNORM_SRGB` など
Pillow が未対応の DX10 形式)は内蔵デコーダで読み直します。Pillow が無くても
BC7 以外は変換できます。BC7 のみ `pip install Pillow` が必要です。

## 制限事項

- FBX 内のアニメーション(Take / AnimationCurve)は変換しません。モーションは配布 VMD を
  使う想定です。
- 物理(剛体・ジョイント)は名前から自動で作る叩き台で、揺れ方は調整していません。
- 準標準ボーン、SDEF は生成しません。必要なら PMXEditor で
  追加してください。
- スフィアマップ・トゥーンテクスチャ、追加 UV、頂点カラーは扱いません。
- マテリアルは拡散テクスチャ 1 枚のみを参照します(法線・スペキュラは使いません)。
- BC7 / BC6H の DDS を変換するには Pillow が必要です。

## うまくいかないとき

| 症状 | 対処 |
| --- | --- |
| MMD で後ろを向いている | `--yaw 180` |
| 面が裏返って見える | `--flip-faces` |
| 大きすぎる / 小さすぎる | `--scale 0.1` のように倍率を直接指定 |
| テクスチャが出ない / 違う画像が貼られる | テクスチャ画像やフォルダを一緒に渡す。それでも違えば `<モデル名>_textures.json` を直して `--texture-map` |
| ボーン名を変えたくない | `--keep-bone-names` |
| VMD を読んでも脚が動かない | 変換ログの「IK: 4 本」を確認。0 本なら足/ひざ/足首の名前が変換されていないので `--bone-map` で指定 |
| モーションで腕が上がりすぎる / 下がりすぎる | `--arm-angle` で腕の角度を調整 |
| 口や目が動かない | `--morph-map` でモーフ名を VMD に合わせる |
| 髪やスカートが揺れない | 変換ログの「物理: …」を確認。対象のボーン名が判定に使う名前を含まないと付かない |
| 髪やスカートが暴れる / 揺れすぎる | PMXEditor で剛体の質量・減衰やジョイントの角度制限を調整。付けたくなければ `--physics none` |
| 色が暗い / 明るすぎる | `--keep-material` で FBX の値のまま出力して比べる |

## 動作確認

```bat
python selftest.py
```

テスト用の立方体 FBX(バイナリ / ASCII)と DDS をその場で作って変換し、頂点数・
面の向き・座標・材質・ウェイトと、DDS デコード・PNG 書き出しを検証します。
あわせて Mixamo 型の骨格を組み立てて MMD 標準ボーン化し、足ＩＫの対象・リンク・
並び順、センター周りの親子関係、両目の回転付与、A スタンス化、モーフ名を検証します。
テクスチャの自動割り当ては、材質ごとに参照の崩れ方が違う FBX(絶対パス・拡張子違い・
未接続・埋め込み・DDS)を作り、期待どおりの画像が選ばれるかと割り当て表の上書きを
検証します。物理は髪とスカートを持つ骨格を組み立て、剛体の種類・ジョイントのつながり・
カプセルの向き・衝突設定・PMX への書き出しと読み直しを、ウィンクは左右の分け方を
検証します。
