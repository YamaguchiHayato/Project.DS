# fbx2pmx — FBX / ゲームのモデルを MMD の PMX・VMD へ変換するツール

FBX ファイルやゲーム(k2Engine)の tkm / tks / tka を、MikuMikuDance (MMD) /
PMXEditor で使える **PMX 2.0(モデル)** と **VMD(モーション)** へ変換します。
Python だけで動き、Autodesk FBX SDK も Blender も不要です。

| 入力 | 出力 |
| --- | --- |
| FBX(バイナリ 7.x / ASCII)のモデル | PMX 2.0 |
| FBX のアニメーション(Mixamo などのダンス・モーション) | VMD |
| ゲームの `.tkm`(モデル)+ `.tks`(骨格) | PMX 2.0 |
| ゲームの `.tka`(アニメーション) | VMD |

- 必要環境: Python 3.8 以降(追加ライブラリ不要。BC7 の DDS とプレビュー画像だけ Pillow を使う)
- 人型モデルは **足ＩＫ・準標準ボーン付きの MMD 標準ボーン構造**に整えるので、
  ネットで配布されているモーション(VMD)をそのまま流せます
- 髪・スカート・袖などには **剛体とジョイント(物理)を自動で付けます**
- 表情モーフの無いモデル(ゲームの tkm など)には、**まばたき・笑い・ウィンク・あいうえお
  などを顔の形から自動で作ります**(配布モーションの表情キーがそのまま効く)
- テクスチャは自動で割り当て、MMD が読めない DDS は PNG へ変換します

## 使い方

```bat
python fbx2pmx.py model.fbx
```

`model.fbx` と同じ場所に `model.pmx` ができます。Windows では `fbx2pmx.bat` に
ファイルを**ドラッグ＆ドロップ**しても変換できます。

| 落とすもの | できるもの |
| --- | --- |
| モデルの FBX | PMX(アニメーションも入っていれば VMD も) |
| モーションだけの FBX(Mixamo の「スキンなし」など) | VMD |
| FBX + テクスチャ画像(またはフォルダ) | テクスチャを自動で割り当てた PMX |
| ゲームの `.tkm` | PMX(同じ名前の `.tks` を骨格に使う。`.tks` も一緒に落としてよい) |
| ゲームの `.tka` | VMD(ボーン数が合う `.tks` を自動で探す) |

> **tkm には骨格が入っていません。** ボーンは同じ名前の `.tks` に入っているので、ゲームの
> `Game/Assets/modelData/player` のように `.tkm` と `.tks` が並んだフォルダから落とすか、
> 2 つを一緒に落としてください。`.tks` が見つからないときは変換を止めて知らせます
> (骨格なしで変換するとボーン 1 本の置物になり、モーションが当たらないため)。

変換した PMX の確認は `pmxpreview.bat` へ **PMX(と必要なら VMD)をドラッグ＆ドロップ**
します。VMD も落とした場合は何フレーム目を描くか聞かれ、正面と横から見た画像を
`<モデル名>_preview.png` に作って開きます。画像は PMX に割り当てたテクスチャの色で
塗るので、テクスチャの当たり間違い(顔に服の画像が貼られている など)もここで分かります。

### コマンドで動かすとき(Windows)

1. エクスプローラーでこのフォルダ(`Tools\fbx2pmx`)を開く
2. アドレスバーに `cmd` と入力して Enter を押す(このフォルダで黒い画面が開く)
3. 下の例のように `python ファイル名.py …` と入力して Enter を押す

ファイルのパスは、エクスプローラーからファイルを黒い画面へドラッグ＆ドロップすると
入力できます。

```bat
rem 出力先を指定
python fbx2pmx.py model.fbx -o out\model.pmx

rem テクスチャ画像やフォルダを一緒に渡す(割り当ての候補になる)
python fbx2pmx.py model.fbx body.png face.png hair.png -o out
python fbx2pmx.py model.fbx --texture-dir D:\download\model\textures -o out

rem ゲームのモデルとモーション
python fbx2pmx.py ..\..\Game\Assets\modelData\player\player.tkm ..\..\Game\Assets\animData\player\Walk.tka -o out

rem モーションだけ変換(Take の選択や一覧表示もできる)
python fbx2vmd.py dance.fbx -o out
python fbx2vmd.py dance.fbx --list-takes

rem 変換結果を画像で確認(Pillow が必要)
python pmxpreview.py out\model.pmx out\dance.vmd --frame 120
```

### 主なオプション(fbx2pmx.py)

| オプション | 説明 |
| --- | --- |
| `-o, --output PATH` | 出力する `.pmx` のパス、または出力フォルダ |
| `--scale N` | 座標に掛ける倍率。指定すると体格合わせは行わない |
| `--unit {mmd,meter,raw}` | `--scale` 省略時の基準。既定は `mmd`(1 単位 ≒ 8cm) |
| `--fit {auto,none}` | `auto`(既定)は脚の長さを標準体格に合わせて縮尺を決める |
| `--leg-length N` | 体格合わせで目標にする脚の長さ(既定 9.5) |
| `--yaw {auto,角度}` | Y 軸まわりの回転。`auto` はつま先ボーンから正面を推定 |
| `--max-weights {1,2,4}` | 1 頂点あたりの最大ボーン数(既定 4) |
| `--keep-bone-names` | ボーン名を MMD 標準名へ変換せず元のまま出力 |
| `--bone-map JSON` | `{"元のボーン名": "MMDボーン名"}` の JSON で名前を上書き |
| `--rig {mmd,none}` | `mmd`(既定)は標準ボーン構造・足ＩＫ・両目を整える |
| `--no-semi-standard` | 腕捩・手捩・肩P・腰・足IK親・足D 系の準標準ボーンを作らない |
| `--arm-angle {auto,off,角度}` | 腕の下がり角。`auto` は T スタンスか下ろしすぎのときだけ 35 度へ直す |
| `--keep-morph-names` | 表情モーフ名を `あ` `まばたき` などへ変換しない |
| `--morph-map JSON` | `{"元のモーフ名": "MMDのモーフ名"}` の JSON で名前を上書き |
| `--no-wink` | `まばたき` `笑い` から `ウィンク` 系のモーフを作らない |
| `--no-auto-face` | 表情モーフが無いモデルでも、表情モーフを顔の形から作らない |
| `--physics {auto,none}` | `auto`(既定)は髪・スカート・袖などに剛体とジョイントを付ける |
| `--physics-target {k2engine,mmd}` | 物理を読み込む側。`k2engine`(既定)はゲームのエンジンがボーン追従の剛体を 75% に縮めて使う分を見込んで大きめに書き出す。MMD で使うなら `mmd` |
| `--no-bust-physics` | 胸を揺らさない(既定では胸のボーン `bust` `breast` `胸` などに揺れを付け、胸の付け根に当たり判定も置く) |
| `--keep-material` | 材質の色・トゥーン・輪郭線・両面描画を MMD 向けに調整しない |
| `--no-motion` | FBX にアニメーションがあっても VMD を書き出さない |
| `--skeleton TKS` | ゲームの `.tkm` / `.tka` に使う骨格を指定(既定: 自動で探す) |
| `--tk-up {z,y}` | `.tkm` / `.tka` の上方向の軸(既定 `z` = 3ds Max の書き出し) |
| `--name` / `--comment` | PMX のモデル名・コメント |
| `--texture-dir DIR` | テクスチャを探すフォルダを追加(複数指定可) |
| `--texture-map JSON` | `{"材質名": "画像"}` の JSON で割り当てを指定(`null` でテクスチャなし) |
| `--copy-textures` | 出力先の中にある画像も含め、すべて出力先へコピー |
| `--no-convert-textures` | DDS など MMD が読めない画像を PNG へ変換しない |
| `--texture-format {png,tga}` | 変換したテクスチャの出力形式(既定 `png`) |
| `--texture-max-size N` | テクスチャの長辺が N を超える場合に縮小 |
| `--no-morph` | ブレンドシェイプをモーフへ変換しない |
| `--no-edge` / `--double-sided` | マテリアルの輪郭線を切る / 両面描画にする |
| `--flip-faces` | 面の表裏が逆になったときに巻き順を反転 |

## 変換される内容

| 元データ | PMX / VMD | 備考 |
| --- | --- | --- |
| メッシュ(複数可) | 1 つのモデルへ統合 | 多角形は三角形に分割 |
| 法線 / UV | 頂点法線 / UV | FBX の UV は上下反転(PMX は原点左上)。tkm はもともと左上原点なのでそのまま |
| マテリアル | 材質 | MMD 向けに調整(「見た目の調整」) |
| テクスチャ | テクスチャ(拡散のみ) | 自動割り当て・DDS は PNG へ変換 |
| スキン | BDEF1 / BDEF2 / BDEF4 | 影響度上位 N 本を正規化 |
| ボーン階層 | ボーン | バインドポーズ基準。標準名へ読み替え |
| ブレンドシェイプ | 頂点モーフ | `あ` `まばたき` などへ読み替え。`ウィンク` 系を追加 |
| — | 足ＩＫ / グルーブ / 両目 / 準標準ボーン | 人型モデルに自動追加 |
| — | 剛体 / ジョイント | 揺れものと当たり判定を自動生成 |
| — | 表示枠 | センター / 体(上) / 腕 / 指 / 体(下) / 足 / 表情 / その他 |
| アニメーション | VMD | ボーンの回転・センター・足ＩＫ・表情 |

### 座標系・単位

FBX は右手座標系で、上方向や正面方向はファイル内の `GlobalSettings`
(`UpAxis` / `FrontAxis` / `CoordAxis`) で決まります。ゲームの tkm / tks / tka は
3ds Max の座標のまま(右手系・Z 上・正面 -Y)です。どちらも **PMX の左手座標系
(Y 上・正面 -Z)** へ変換し、鏡像変換になる分だけ面の巻き順を戻します。

縮尺は、人型なら**脚(股関節〜足首)の長さを 9.5 単位**にそろえます。これは MMD の
縮尺(1 単位 ≒ 8cm)で身長 158cm の人の脚の長さ(身長の約 48%)にあたります。配布
モーションのセンター移動や足ＩＫの位置は絶対値なので、体格をそろえるとステップ幅や
足の位置が合いやすくなります。人型でないモデルは FBX の `UnitScaleFactor` から実寸を
求め(tkm は単位情報が無いので 1 単位 = 1cm とみなす)、1 単位 ≒ 8cm に合わせます。

### ボーン名の MMD 標準名への変換

Mixamo (`mixamorig:Hips`)、Autodesk の `Character1_*`、3ds Max の Biped (`Bip001 *`) と
CAT (`Base HumanLArmUpperarm`)、Unity Humanoid / VRM 風 (`LeftUpperArm` `UpperArm.L`)、
SapphiArt 風 (`Leg_L` / `Knee_L`) の名前を、`センター` `上半身` `首` `頭` `左腕` `左ひじ`
`左手首` `左足` `左ひざ` `左足首` `左親指０` … といった MMD 標準名へ読み替えます
(元の名前は英語名欄に残します)。名前だけでは決まらないものは骨格全体を見て判断します。

- 全ボーン共通の接頭辞(`Zombie_` `Base Human` `SapphiArt_19:` など)は外して比べる
- `Knee` があれば `Leg` は太もも(足)、無ければすね(ひざ)とみなす
- 背骨は `Spine` `Spine1` `Chest` `Ribcage` などの並び順で `上半身` `上半身2` `上半身3`

VMD のボーン名・モーフ名は 15 バイト(Shift-JIS)までしか入らないので、標準名に
ならなかった長い名前(`J_L_HeadRibbon_00` など)は、共通接頭辞や区切り文字を外して
15 バイト以内に縮めます(`JLHeadRibbon00`)。

## 配布モーション (VMD) を使う

ネットで配布されているダンス・ライブ用のモーション(.vmd)は、MMD 付属の
初音ミクに倣った「標準ボーン」を前提に作られています。人型のモデルは、変換時に
自動でこの構造に整えます(`--rig mmd`、既定)。MMD でモデルを読み込んだあと、
VMD をそのまま読み込めば動きます。

| 整える内容 | 中身 |
| --- | --- |
| 親子関係 | `全ての親` → `センター` → `グルーブ` → `腰` → `上半身` / `下半身` |
| 足ＩＫ | `左足ＩＫ`(対象 `左足首`、リンク `左ひざ`・`左足`、ひざは前にだけ曲がる)と `左つま先ＩＫ`、まとめて動かす `左足IK親`。右も同様 |
| つま先 | つま先ボーンが無いモデルは、足首に乗っている頂点の最前端に補う |
| 両目 | `左目` / `右目` に回転を付与する `両目` |
| 腕捩・手捩 | 腕・ひじの軸まわりにひねるボーン。上腕・前腕の頂点を、付け根からの位置に応じて 0〜100% ひねるよう配分(元のひねり用ボーンがあればその頂点も含める) |
| 肩P | 肩だけを動かす `肩P` と、腕への影響を打ち消す `肩C` |
| 腰 | `腰` と、脚への影響を打ち消す `腰キャンセル` |
| 足D | IK を解いた後の脚の回転をそのまま受け取る `足D` `ひざD` `足首D` と `足先EX`。脚の頂点はこちらへ移す |
| 腕の角度 | T スタンス(ほぼ水平)や下ろしすぎ(50 度超)のモデルは 35 度の A スタンスに直す(メッシュも一緒に回す) |
| 表情モーフ | `MTH_a` → `あ`、`EYE_blk` / `Blink` → `まばたき` など。`まばたき` を左右に分けて `ウィンク` / `ウィンク右`、`笑い` から `ウィンク２` / `ウィンク２右` を作る |

人型と判定できない(上半身や左右の足が無い)小物や武器には適用しません。準標準ボーンに
キーの無い(標準ボーンだけの)モーションでは、準標準ボーンの有無で見た目は変わりません。

## FBX のモーション → VMD

Mixamo などで配布されている FBX のモーションを VMD へ変換します。モデル変換と同じ
手順で骨格を MMD 標準ボーン構造に整えてから、各フレームの姿勢をその骨格の動きに
直すので、変換した PMX にも一般的な MMD モデルにも使えます。

- ボーンの回転は、バインドポーズからの差分を PMX の親ボーンからの相対回転にする
- `センター`(と元の骨格にある移動するボーン)の移動、`足ＩＫ` / `つま先ＩＫ` の位置も入れる
- T スタンスの元データは、PMX の腕を A スタンスにした分を打ち消して元の動きを再現する
- ブレンドシェイプの曲線は表情モーフのキーにする
- 毎フレームのキーは、補間で再現できるもの(誤差 0.1 度未満)を間引く

`fbx2pmx.py` にアニメーション付きの FBX を渡すと、PMX と一緒に同じ名前の VMD も
書き出します(`--no-motion` で無効化)。Take を選ぶときは `fbx2vmd.py --take 名前`。

## ゲームのモデル・モーション (tkm / tks / tka)

ゲーム(k2Engine)が使う独自形式も変換できます。

| ファイル | 中身 | 変換先 |
| --- | --- | --- |
| `.tkm` | メッシュ・材質・スキン | PMX(同じ名前の `.tks` を骨格に使う) |
| `.tks` | 骨格(ボーンごとのバインド行列) | — |
| `.tka` | アニメーション(ボーンごと・時刻ごとのローカル行列) | VMD |

`.tkm` の骨格は、一緒に渡された `.tks` → 同じフォルダの同じ名前の `.tks` → 近くのフォルダ
(2 階層上まで)の同じ名前の `.tks` の順に探します。ボーンに乗っているメッシュなのに見つから
ないときはエラーにし、ボーン数が足りない(別のモデルの)骨格もエラーにします。ボーンに乗って
いない置物(地面・箱など)は骨格なしで変換します。

`.tka` の骨格は、一緒に渡された `.tks` か、ボーン数が一致する `.tks` を近くのフォルダから
探します(例: `animData/player/Walk.tka` → `modelData/player/player.tks`)。見つからないときは
`--skeleton` で指定してください。材質はエンジンと同じくアルベド画像の同名 `.dds` を探し、
PNG に変換して使います。UV はエンジンと同じく左上原点のまま使います。

tkm には材質の画像の指定がずれているものがあります(例: player の黒いスカートと眉は
`bodysuit.DDS` を指しているが、UV は `clothes` / `hairhead` の絵に合う)。元は別々だった材質
(白い襟と体など)が 1 つにまとめられていることもあります。そこで UV の島(つながった部品)
ごとに、同じ画像を使うほかの部品と UV が大きく重なり、別の画像ではどの部品とも重ならず
絵の描かれた場所に収まるものは取り違えとみなして付け替えます。材質の一部だけが当てはまる
ときは、その部品を新しい材質(`元の名前_画像名`)に分けます。繰り返し模様の画像(UV が
0〜1 の外へはみ出す部品だけが使う画像)は付け替え先にしません。変換ログに「テクスチャの
取り違えを直しました」と出します(FBX でも同じ判定をします)。

## 表情モーフの自動生成

配布モーション(VMD)は `まばたき` `あ` などの名前で表情を動かすので、モデルに同じ名前の
モーフが無いと表情が固まったままになります。ゲームの tkm には表情(ブレンドシェイプ)が
入っていないため、表情モーフが 1 つも無い人型モデルには、顔の形から次のモーフを作ります
(`--no-auto-face` で止められます)。

| モーフ | 作り方 |
| --- | --- |
| `口角上げ` `口角下げ` `にやり` `まるい口` `ワ` | 口角の上げ下げと口の開き・幅の組み合わせ。母音も少し口角を上げて柔らかい口元にする |
| `上` `下` `にこり` `困る` `怒り` `真面目` | 目の少し上にある小さな部品(眉)を上下・内側の上げ下げ・弧で動かす |
| `柔らかな笑み` | 口角上げと眉のにこり(目は開けたまま) |
| `ウィンク2` `ウィンク2右` | 半角の「2」で書かれた配布モーション用に、`ウィンク２` 系と同じ形の別名 |
| `まばたき` / `笑い` | 目のボーン(`左目` `右目`)に乗る瞳の頂点から目の大きさを測り、目の奥を通る軸で上まぶたを下まぶたまで回して閉じる。白目は押し縮め、瞳は奥へ隠す。`笑い` は閉じた線が上へ弧を描く |
| `ウィンク` 系 | `まばたき` `笑い` を左右に分けて作る(`ウィンク` `ウィンク右` `ウィンク２` `ウィンク２右`) |
| `あ` `い` `う` `え` `お` | 唇の合わせ目(閉じていても上唇と下唇が別の頂点になっている切れ目)を探し、その下側(下唇・口の中・下の歯・あご)を顎の軸で回して下げる。`い` `え` は口角を広げ、`う` `お` はすぼめる |
| `ぺろっ` | 口の前へ飛び出している小さな部品(舌)があれば普段は口の中へしまい、このモーフで出す |

- 前髪や眉など、顔とつながっていても目から離れている部品は動かしません。
- 顔の作りはモデルごとに違うので叩き台です。開き方が足りない・形が気になるときは
  PMXEditor で調整してください。元の FBX にブレンドシェイプ(表情)が入っているなら、
  FBX から変換するとそちらを使います(自動生成より正確です)。

## 物理(髪・スカートの揺れ)

元データには物理演算の情報が入っていないので、ボーン名と頂点の付き方から剛体と
ジョイントの叩き台を自動で作ります(`--physics auto`、既定)。

| 対象 | 判定に使う名前(ボーン名の一部) | 作るもの |
| --- | --- | --- |
| 髪 | `hair` `髪` `bangs` `pony` `twintail` `ahoge` など | 物理演算のカプセル + ジョイント |
| リボン | `ribbon` `リボン` | 同上(形を保つよう硬め) |
| スカート | `skirt` `スカート` `dress` `cape` `coat` など | 同上 |
| 袖 | `sode` `sleeve` `袖` `cuff` | 同上 |
| その他 | `tail` `しっぽ` `string` `紐` `frill` など | 同上 |
| 胸(`--bust-physics`) | `bust` `breast` `胸` `oppai` など | 硬いばねで小さく揺れて戻る |
| 当たり判定 | `頭` `上半身` `下半身` `足` `ひざ` `腕` `ひじ` | ボーン追従のカプセル |

- 揺れもののボーン 1 本ごとに、そのボーンから子ボーンへ伸びるカプセルを置きます。
  先端のボーンは乗っている頂点の広がりから長さを、太さも頂点から決め、左右対になる
  もの(`J_L_xxx` / `J_R_xxx`)はそろえます。
- 連鎖の付け根は親ボーンの当たり判定(髪なら `頭`、スカートなら `下半身`)にジョイントで
  つなぎます。揺れもの同士と付け根の当たり判定とはぶつからず、脚・腕・胴とはぶつかります
  (腰に付くスカートの付け根は、体を曲げたときに押し上げられないよう胴ともぶつけません)。
- 当たり判定は、頭は頭皮の内側に収まる球、`下半身` は腰の横へはみ出さない太さ、脚は
  実際の太さに近いカプセルにします。
- 静止状態で当たり判定に食い込む揺れもの剛体は、食い込まない太さまで細くします
  (重なったままだと初期フレームで暴れるため)。ボーンの線そのものが当たり判定の中にあって
  細くしきれないときだけ、その相手とぶつからない設定にします。変換ログの
  「細くしきれず衝突を外した組」が 0 でなければ、その揺れものはすり抜けることがあります。

- 当たり判定は頭・首・上半身・肩・胸・下半身・脚・腕に付けます(肩は髪が乗る所、胸は
  前に垂れる髪が当たる所)。
- ジョイントの回転の制限は、体の中心へ向かって振れる側だけ狭くします(最大 5 度)。
  スカートは外側へ大きく振れる(前後 90 度・左右 60 度)ので、しゃがんで脚を上げても
  太ももの上に乗ります。脚の当たり判定は太ももの頂点までの距離の中央値の 1.5 倍です(骨と骨の間の布が
  太ももに沈まないよう余裕を持たせる)。
  前髪は別の種類にして振れ幅を小さく・ばねを強くし、目にかからないようにしています。
- 胸を揺らすときは、胸の上に重なる服の頂点に、すぐ下の体の頂点の重みを写します(元の
  モデルは胸を揺らさない前提で、体は胸のボーンに 100% 乗っているのに服は半分ほどしか
  乗っていないことがあり、そのままだと肌が服から飛び出すため)。重みを写すのは、もともと
  胸のボーンに少しでも乗っている部品だけです(ネクタイや襟まで動かして埋めないように)。
- 胸の揺れは軽く(質量 0.05)、強く減衰(0.99)させ、回転は ±4 度までにしています。重いと
  エンジンでは動きに遅れて大きく振れ、肌がネクタイや襟の上へはみ出すためです。
- 重ね着(名前に `outer` `over` `外` を含む外側のスカートなど)は、外側と内側の下の段同士を
  ぶつけて、外側が内側を突き抜けないようにします(腰の付け根の段同士は最初から重なって
  いるのでぶつけません)。
- ジョイントの移動の範囲は ±0.0001 にします(0 ちょうどだと k2Engine が ±0.2 の遊びを
  足し、重力で剛体がずり落ちるため)。
- 制限の向き(+ 側がどちらへ効くか)は、エンジンと同じ Bullet で確かめた向きに合わせて
  います。MMD 本体での向きは未確認です。
  後ろ髪のように節の多い連鎖が前へ回り込んで、体や腕を突き抜けないようにするためです。
- ゲームのエンジン(k2Engine の `PMXPhysics`)はボーン追従の剛体を 75% に縮めて使うので、
  既定(`--physics-target k2engine`)では縮められた後にちょうどの大きさになるよう 1/0.75 倍で
  書き出し、PMX のコメントにその旨を残します(`pmxpreview.py` はそれを読んで同じ縮小で
  再現します)。MMD で使う場合は `--physics-target mmd` で変換してください。

揺れ方(重さ・減衰・ジョイントの角度制限・ばね)はあくまで叩き台です。揺れすぎる・
硬すぎる場合は PMXEditor で調整してください。

## 見た目の調整

ゲーム用の材質の値のままだと、MMD では暗く沈んだり平板に見えたりします。そこで次の
ように調整します(`--keep-material` で無効化)。

- テクスチャのある材質は拡散色を白、環境色を 0.5 にし、色をテクスチャに任せる
- 共有トゥーン `toon01.bmp` を設定し、ゲーム用の強い反射を弱める
- 目まわり(`eye` `目` `瞳` `まつげ` など)と半透明の材質は輪郭線を消す
- 髪・リボン・スカート・袖など薄い板の材質は両面描画にする

## テクスチャの自動割り当て

配布モデルの FBX は、テクスチャの参照が作者の PC の絶対パスのままだったり、拡張子が
違っていたり、そもそも繋がっていなかったりします。そこで材質ごとに次の順で画像を
探します。手がかりにするのは、元ファイルと同じフォルダ(と `textures` などの
サブフォルダ)、一緒に渡した画像、`--texture-dir` のフォルダです。

| 順 | 見つけ方 | 例 |
| --- | --- | --- |
| 1 | 割り当て表(`--texture-map`) | `{"Skin": "body.png"}` |
| 2 | 参照どおり / 同じファイル名 | 参照 `C:\Users\作者\Body_D.tga` → 候補の `Body_D.tga` |
| 3 | 拡張子違い(大文字小文字も無視) | 参照 `Body_D.tga` → 候補の `body_d.PNG` |
| 4 | FBX に埋め込まれた画像を取り出す | `hair.png` を出力先へ書き出す |
| 5 | 材質名などとファイル名の近さで推定 | 材質 `Face` → `Face_BaseColor.png`(`Face_Normal.png` は除外) |
| 6 | 一緒に渡した拡散色の画像が 1 枚だけならそれ | アトラス 1 枚のモデル |

法線・スペキュラ・ラフネス・AO・発光などのマップ(`_Normal` `_nrm` `_spec` `_metallic`
など)は推定の候補から外します。変換ログに材質ごとの結果が出ます。推定や未発見の材質が
あったときは、PMX の隣に `<モデル名>_textures.json` を書き出します。間違っている材質
だけ書き換えて `--texture-map <モデル名>_textures.json` を付けて変換し直せば、次からは
その割り当てで変換されます(1 個ずつ PMXEditor で直す必要はありません)。

```json
{
  "Body": "../tex/body_d.PNG",
  "Face": "../tex/Face_BaseColor.png",
  "Skin": null
}
```

使う画像は PMX のフォルダへコピー(MMD が読めない形式は変換)するので、出力フォルダ
だけで完結します。

## テクスチャの変換 (DDS → PNG / TGA)

MMD が読めるのは BMP / PNG / JPEG / TGA だけで、**DDS は読めません**。DDS など MMD が
読めない画像は、変換時に自動で PNG へ変換して PMX と同じフォルダへ書き出します
(`--no-convert-textures` で無効化)。テクスチャだけを変換したいときは単体でも使えます。

```bat
python texconv.py utc_all2.DDS                       rem 同じ場所に .png を作る
python texconv.py ..\..\Game\Assets\modelData -o tex rem フォルダ内の DDS をまとめて
python texconv.py normal.DDS --format tga --max-size 1024
```

| 形式 | 内蔵デコーダ | Pillow |
| --- | --- | --- |
| DXT1 / DXT3 / DXT5 (BC1/BC2/BC3) | ○ | ○ |
| BC4 / BC5 (ATI1 / ATI2) | ○ | ○ |
| 無圧縮 RGB / RGBA / BGRA (マスク指定・DX10 含む) | ○ | 一部不可 |
| BC7 / BC6H | × | ○ |

Pillow が入っていればまず Pillow で読み、読めない形式(`B8G8R8A8_UNORM_SRGB` など)は
内蔵デコーダで読み直します。BC7 のみ `pip install Pillow` が必要です。

## 確認ツール

```bat
rem 中身の一覧と整合性チェック
python pmxinfo.py model.pmx --materials --bones --morphs --physics

rem 正面と横からの画像(VMD の指定フレームの姿勢・剛体の重ね描きもできる)
python pmxpreview.py model.pmx dance.vmd --frame 120 -o pose.png
python pmxpreview.py model.pmx --bodies
python pmxpreview.py model.pmx dance.vmd --frame 120 --no-physics
```

`pmxpreview.py` は IK・回転付与・表情モーフ(VMD の表情キー)まで計算する簡易版 MMD です。
髪・スカートなどの揺れものも簡易物理演算で動かします。揺れもの剛体を「付け根を支点に
振れる棒」とみなし、指定フレームの 2 秒前からモーションを流して、重力・ばね・ジョイントの
回転の制限・当たり判定(ボーン追従の剛体)で動かす近似です(MMD の物理演算と完全には
一致しません)。スカートが脚を、髪が顔を突き抜けていないかの確認に使えます。物理なしの
姿勢を見たいときは `--no-physics`。
テクスチャは画素ごとに貼り、陰影も頂点の法線からなめらかに付けるので、ゲーム内に
近い見た目で確認できます(縦横 2 倍で描いて縮小するので輪郭もギザギザしません)。
材質は MMD と同じ順に描き、両面描画でない材質は裏側を描きません。読めないテクスチャが
あれば名前を表示して、その材質だけ材質の色で塗ります。形だけ見たいときは `--no-texture`
で灰色に、細かいところを見たいときは `--size 1400` のように大きくして描けます。

## 制限事項

- 物理(剛体・ジョイント)は名前から自動で作る叩き台で、揺れ方は調整していません。
- FBX の曲線はキーの間を線形に補間します(配布モーションは毎フレームにキーがある
  ことがほとんどなので通常は問題ありません)。
- 元の骨格で `上半身` の付け根が腰から離れている場合(Mixamo など)、腰を大きく傾ける
  モーションでは上半身の付け根がわずかにずれます(MMD の `上半身` は移動できないため)。
- 元の骨格のひねり用ボーンは `腕捩` / `手捩` に置き換えるので、モーション変換では
  肩から上腕にかけての頂点がわずかに元とずれます。
- SDEF、スフィアマップ、トゥーンテクスチャ、追加 UV、頂点カラーは扱いません。
- マテリアルは拡散テクスチャ 1 枚のみを参照します(法線・スペキュラは使いません)。

## うまくいかないとき

| 症状 | 対処 |
| --- | --- |
| MMD で後ろを向いている | `--yaw 180` |
| 面が裏返って見える | `--flip-faces` |
| 大きすぎる / 小さすぎる | `--scale 0.1` のように倍率を直接指定(体格合わせは止まる) |
| テクスチャが出ない / 違う画像が貼られる | テクスチャ画像やフォルダを一緒に渡す。それでも違えば `<モデル名>_textures.json` を直して `--texture-map` |
| VMD を読んでも脚が動かない | 変換ログの「IK: 4 本」を確認。0 本なら足/ひざ/足首の名前が変換されていないので `--bone-map` で指定 |
| モーションで腕が上がりすぎる / 下がりすぎる | `--arm-angle` で腕の角度を調整 |
| 口や目が動かない | 変換ログの「表情モーフ」を確認。FBX のモーフ名が違うときは `--morph-map` で VMD に合わせる。tkm で作られないときは `左目` `右目` `頭` のボーンが見つかっていない |
| スカートが脚を / 髪が顔をすり抜ける | 変換ログの「細くしきれず衝突を外した組」を確認。0 でなければ PMXEditor で該当の剛体を細くし、非衝突グループを外す |
| 髪やスカートが揺れない | 変換ログの「物理: …」を確認。対象のボーン名が判定に使う名前を含まないと付かない |
| 髪やスカートが暴れる / 揺れすぎる | PMXEditor で剛体の質量・減衰やジョイントの角度制限を調整。付けたくなければ `--physics none` |
| 色が暗い / 明るすぎる | `--keep-material` で元の値のまま出力して比べる |
| `.tka` の骨格が見つからない | `--skeleton ..\modelData\xxx\xxx.tks` で指定 |
| 「骨格のファイル xxx.tks が見つかりません」 | `.tkm` と同じ名前の `.tks` を同じフォルダに置くか、一緒にドロップする |
| モーションを当てても動かない | `pmxinfo.py` でボーン数を確認。1 本なら骨格なしで変換されているので変換し直す。プレビューに「モデルに無い標準のボーン」が出ていないかも確認 |
